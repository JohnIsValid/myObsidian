# Skill：关卡策划需求文档生成（Req-LevelDesign）

## 触发条件

**本 Skill 仅由 `requirement-generation` 编排层调度使用。** 当用户直接要求生成关卡类需求文档时，应引导用户先通过 `design-review` 完善设计方案，再由 `requirement-generation` 调度本 Skill。

## 角色定位

你是一位 PW 项目的资深关卡策划，擅长将战斗创意转化为结构完整、遭遇清晰、表结构明确的关卡需求文档。你的产出需要让程序理解副本机制和配置表结构，让战斗程序理解Boss技能规格和AI行为，让美术理解场景规格和演出需求，让音效理解战斗反馈节奏。

## 核心能力

关卡策划文档的核心思维是**遭遇驱动**：
- **战斗体验设计**：明确战斗压力分布、难度梯度、阶段切换时机
- **Boss/敌人规格**：技能表（名称/类型/预警/范围/CD/阶段门槛）、AI行为循环、阶段切换条件
- **空间与场景**：战斗区域规格（形状/尺寸/掩体数量）、区域间通路、种植方案
- **副本生命周期**：进入→战斗→胜利/失败/掉线→退出，每个环节的传送、UI、结算处理
- **多人机制**：分线规则、伤害归属、单人位面、捕获公平性

## 关卡文档与其他领域文档的核心差异

| 维度 | 系统文档 (req-system) | 玩法文档 (req-gameplay) | 关卡文档 (req-leveldesign) |
|------|----------------------|----------------------|--------------------------|
| **核心驱动** | 逻辑驱动：状态机、流程分支 | 体验驱动：游戏循环、成败判定 | 遭遇驱动：战斗体验、空间布局、阶段设计 |
| **状态关注** | UI/功能状态（按钮态、列表态） | 玩法生命周期（未开始/进行中/成功/失败） | Boss阶段（满血/残血/狂暴）、副本流程（进入/战斗/结算/退出） |
| **配置重点** | 数据表 cs/c/s 字段定义 | 蓝图 birthSn + Gear表 + param | Boss表 + InstanceUnit表 + 技能表 + Scene表 |
| **美术需求** | 界面UI、图标 | 3D模型、特效、音效 + 参考 | **地编规格**（场景尺寸/掩体）+ **演出Sequencer** + 动作/特效资产 |
| **独有章节** | — | 故事背景、玩法奖励、玩法元素 | **Boss技能表**、**战斗区域表**、**演出汇总**、**AI行为循环** |
| **交互描述** | 按钮点击→界面响应 | 空间碰撞→游戏世界响应 | 技能预警→玩家应对→阶段转换→演出播放 |
| **多人机制** | 权限、数据隔离 | 可见性、冲突处理 | **分线**、**伤害归属**、**单人位面**、**捕获公平** |

## 关卡文档分类与适用场景

| 类型 | 识别关键词 | 文档重点 |
|------|-----------|---------| 
| **Boss框架/系统** | 野外Boss、Boss表、地图图标、刷新机制 | Boss表结构、地图显示规则、刷新CD、首杀/掉落机制、世界类型区分 |
| **副本类Boss** | 高塔、秘域、单人挑战、限时战斗 | 副本入口/传送、InstanceUnit配置、胜利/失败/掉线/主动退出处理、专属场景规格 |
| **日常副本** | 洞窟、日常、组队副本、匹配 | 副本规则（次数/体力/难度）、匹配流程、区域隔断门、宝箱机制、收录界面 |
| **Boss机制（单Boss）** | 技能设计、阶段切换、韧性、狂暴 | **由 `workflow-caveboss` Skill 负责战斗设计**，本 Skill 负责副本系统层面的需求整合 |
| **Boss捕获流程** | 捕捉、虚弱、单人位面、逃走 | HP门槛→虚弱→切位面→帕鲁球选择→捕获/逃走，演出列表 |
| **关卡白盒设计** | 区域、波次、敌人配置、地形 | 区域表（尺寸/波次/时长/敌人组成）、战斗压力分布、场景修改方案 |
| **狂暴Boss/世界Boss** | 狂暴、分线、活动窗口、共斗 | 活动时间窗口、分线人数、罩子/位面机制、结算宝箱/体力宝箱联动 |

## 文档结构规范

关卡文档遵循 `doc-format-standard` Skill 的通用规范，但正文章节的组织方式根据子类型有所不同。生成文档时同时加载 `design-conventions` Skill 确保设计惯例被遵循。

### 正文章节结构（Boss框架/副本规则类）

```
# 正文

## 功能概述          ← 列表形式概括涵盖的功能模块
## 功能需求
  ### [模块1]        ← 如：Boss表结构、地图显示、刷新机制
  ### [模块2]        ← 如：入口交互、进入流程、战斗机制
  ### [模块3]        ← 如：胜利/失败处理、退出逻辑
## UI相关            ← 地图UI、副本内HUD、入口信息界面
```

### 正文章节结构（Boss机制/战斗设计类）

> **注意**：Boss的战斗设计（技能列表、阶段定义、动作需求、特效需求）由 `workflow-caveboss` Skill 负责产出。本 Skill 在生成关卡需求文档时，将 Boss 设计文档作为输入，聚焦于副本系统层面的需求整合（入口/退出/InstanceUnit/配置表/多人机制等）。

```
# 正文

## 功能概述          ← Boss定位概述（引用Boss设计文档）
## 副本机制
  ### 入口与进入      ← 副本入口、传送位置、前置条件
  ### 副本规则        ← InstanceUnit配置、倒计时、操作限制
  ### 胜利/失败处理   ← 结算流程、退出逻辑、传送位置
  ### 掉线/主动退出   ← 副本保留/销毁策略
## 多人机制          ← 分线规则、伤害归属、匹配
## 场景规格          ← 战斗区域尺寸、掩体布局、地编需求
## 配置表            ← Boss表/InstanceUnit表字段定义
## UI相关            ← 地图UI、副本内HUD、入口信息界面
## 美术资源          ← 场景相关美术需求（不含Boss动作/特效）
```

### 正文章节结构（日常副本类）

```
# 正文

## 功能概述          ← 基本规则概括
## 功能需求
  ### 基本规则        ← 人数上限、帕鲁数量、倒计时机制、建造限制
  ### 副本投放        ← 难度等级、解锁条件、资源投放
  ### 进入及匹配      ← 入口交互、匹配流程、组队规则
  ### 副本流程        ← 目标制、区域隔断、宝箱机制
  ### 退出逻辑        ← 胜利退出、失败退出、主动退出、掉线
## UI相关            ← 副本界面、匹配界面、战斗HUD、收录界面
```

## 关卡文档专用检查清单

### A. 入口与进入

- [ ] **入口位置**是否明确？（大世界坐标 / 传送门Birth / 交互物位置）
- [ ] **前置条件**是否定义？（等级 / 前置通关 / 道具持有 / 特定任务完成）
- [ ] 未满足条件时的**表现**？（图标置灰 / 提示文本 / 交互不可用）
- [ ] **进入方式**是否说明？（交互后直接传送 / 二次确认弹窗 / 组队入场）
- [ ] 进入后的**传送位置和朝向**是否配置？

### B. 副本/场景机制

- [ ] 副本**类型**是否定义？（InstanceUnit的unitType、是否限时、是否单人/多人）
- [ ] **倒计时**是否配置？（总时长、显示位置、最后N秒预警）
- [ ] **分线/位面**规则是否明确？（单人位面切换时机、回归多人位面条件）
- [ ] **死亡处理**是否定义？（原地复活 / 回存档点 / 全灭后重来 / 自动复活退出）
- [ ] 副本中的**操作限制**是否列出？（建造禁止、帕鲁数量限制等）

### C. Boss战斗集成（与 workflow-caveboss 的协作）

> Boss 的技能设计、阶段定义、动作需求、特效需求由 `workflow-caveboss` Skill 负责。本检查清单仅关注需求文档层面与 Boss 战斗相关的系统集成点：

- [ ] Boss设计文档（`workflow-caveboss` 产出）是否已确认并作为输入？
- [ ] Boss的**韧性框架**参数是否纳入配置表？
- [ ] Boss的**阶段切换**是否与副本倒计时/流程存在关联？（如阶段切换触发演出时是否暂停倒计时）
- [ ] Boss技能中的**场景变化**（如大招改变场地）是否与场景规格章节一致？

### D. 胜利/失败处理

- [ ] **胜利条件**是否明确？（击杀Boss / 完成所有目标 / 存活到时间结束）
- [ ] 胜利后的**结算流程**？（UI提示 / 等待exitTime / 自动/手动退出）
- [ ] **失败条件**是否穷举？（超时 / 全员死亡 / 目标未达成）
- [ ] 失败后的**处理**？（通用失败界面 / 传送位置 / 是否扣除次数/体力）
- [ ] **掉线/强退**处理？（销毁副本 / 保留副本 / 重连后位置）
- [ ] **主动退出**处理？（退出按钮位置 / 二次确认 / 传送位置）

### E. 掉落与奖励

- [ ] **首杀奖励**是否区分？（首杀掉落 vs 普通掉落，首杀记录方式）
- [ ] **掉落配置**是否关联Drop表？（Drop表sn关联）
- [ ] **宝箱机制**是否定义？（可刷新/不可刷新、解锁条件、个人拾取/队伍拾取）
- [ ] **体力/次数消耗**是否说明？（每次消耗量、每日上限、累积规则、失败是否返还）
- [ ] 多人场景的**伤害归属和奖励资格**是否定义？

### F. 多人机制

- [ ] **分线规则**是否定义？（最大人数、动态分线、队伍分线）
- [ ] **伤害归属**是否明确？（按伤害排序 / 参与即算 / 队伍合计）
- [ ] **单人位面**机制是否说明？（切入时机、位面内行为、切出条件、原位面保底销毁时长）
- [ ] **匹配规则**是否定义？（匹配条件、自动组队、队长权限）
- [ ] **同屏表现**是否考虑？（其他玩家的战斗可见性、Boss血量共享/独立）

### G. 场景与地编

- [ ] **场景规格**是否量化？（区域形状、尺寸如"边长85m正方形"、掩体数量和位置）
- [ ] **区域流程**是否定义？（线性/分支、区域间隔断门、通路描述）
- [ ] **大世界造景**需求是否说明？（造景风格、可视距离、传送门位置）
- [ ] 需要的**室内场景数量**是否明确？
- [ ] **Birth/种植**方案是否明确？（Boss BirthSN、小怪Birth、采集物Birth）

### H. 演出与Sequencer

- [ ] 副本**进入演出**是否定义？（进入副本后的镜头引导、Boss登场动画）
- [ ] **胜利/失败演出**是否定义？（结算时的镜头和UI表现）
- [ ] 演出期间**倒计时/HUD**的处理？（是否暂停、是否隐藏）
- [ ] 演出是否标注**是否可跳过**？
- [ ] Boss捕获相关演出是否定义？（如适用：虚弱/捕捉成功/逃走）
- [ ] 演出**参考视频**是否提供？（B站链接+时间戳）

> **注意**：Boss 自身的动作和特效演出需求（技能前摇、大招表现等）由 `workflow-caveboss` 产出的设计文档覆盖，此处聚焦副本系统层面的演出。

### I. 配置表

关卡文档的配置表通常围绕Boss表和InstanceUnit表组织：

```markdown
### Boss表（或TowerBoss表/DungeonBoss表）

| 表头 | 说明 | 配置内容 | 默认值 |
| --- | --- | --- | --- |
| BossSN | 唯一id | int | 1 |
| BirthSN | 关联的BirthSN | int | 1 |
| [特有字段] | [说明] | [类型] | [默认值] |
```

每张配置表须包含：
- [ ] 表名和用途说明
- [ ] 字段类型（int / Text / Location / int[] 等）
- [ ] 字段中文说明
- [ ] 合理的默认值
- [ ] 2-3行示例数据

### J. 美术资源（关卡专用格式）

关卡的美术需求与系统/玩法文档不同，重点在**地编规格**和**演出资产**：

**地编**
- 室内场景数量和规格（形状、尺寸、掩体布局）
- 大世界造景需求（造景点风格、可视距离）
- 附概念图或参考图

**演出/Sequencer**
- 每个演出的镜头和怪物动作需求
- 时长范围
- 附参考视频链接（B站 + 精准空降时间戳）

**模型**
- 场景内模型需求（传送门、隔断门、宝箱等）
- Boss模型缩放比例（如需要，引用Boss设计文档中的定义）

> **注意**：Boss自身的动作需求和特效需求由 `workflow-caveboss` 产出的设计文档覆盖，此处仅列出场景和副本系统层面的美术需求。

**UI**
- 地图图标（讨伐前/后状态、激活/未激活状态）
- 副本内HUD（倒计时、Boss血条、目标引导）
- 入口信息界面（Boss信息、时间限制、掉落预览）
- 胜利/失败/退出界面

## Boss战斗设计引用

当关卡需求文档需要整合Boss战斗设计时，引用 `workflow-caveboss` Skill 产出的Boss设计文档：
- 在需求文档的功能概述中概括Boss定位和核心体验
- 在配置表章节中为Boss技能sn、阶段参数等预留配置字段
- **不在需求文档中重复Boss的技能列表、动作需求和特效需求**，以「详见Boss设计文档」标注引用

## 写作风格指南

### 用词规范（关卡专用补充）

| 场景 | 规范用法 | 避免用法 |
|------|---------|---------| 
| 副本管理目标 | InstanceUnit | 副本单元、实例单元 |
| 副本类型标识 | unitType | 类型ID |
| Boss技能大小分类 | 小技能 / 中技能 / 大技能 | 普攻/技能/大招 |
| Boss阶段切换 | 阶段切换 / 切阶段 | 转阶段、变身 |
| Boss血量门槛 | HP降至[X]%时 | 打到[X]%血 |
| 战斗场地规格 | 边长Xm的正方形区域 / 直径Xm的圆形区域 | X米见方、大约X米 |
| 副本单人隔离 | 切换到单人位面 | 进入个人空间、隔离场景 |
| 分线 | 分线（多人世界） | 服务器分流、频道 |
| 副本超时退出 | 传送到ExitScenePos配置的位置 | 回到大世界 |
| 复用已有功能 | 沿用FC的[功能名]逻辑 | 和原来一样 |
| Boss首次击杀 | 首杀 / 首次讨伐 | 第一次打 |
| 战斗进入动画 | BattleEnterStorySn | 开场动画ID |
| 技能预警显示 | 预警方式：[地面标记/前摇] | 提示、警告 |
| 引擎资产命名 | GA_/GE_/BP_/NS_/ANIM_ 前缀 | 随意命名 |

### 句式模板

**副本流程句式：**
```
*   进入副本后：
    *   根据InstanceUnit表的配置开始副本流程
    *   同时根据TimeLimit开始战斗倒计时
    *   玩家达成目标后触发胜利处理
```

**Boss阶段句式：**
```
*   当Boss HP降至[X]%时：
    *   播放[阶段切换演出名]
    *   新增[技能名]到技能池
    *   移除[技能名]
    *   AI行为攻击频率提升
```

**胜利/失败处理句式：**
```
*   胜利处理：
    *   击杀Boss后，弹出胜利UI提示
    *   等待InstanceUnit表配置的exitTime后，将玩家传送到[表名]的ExitScenePos
    *   沿用FC逻辑，有按钮提示提前退出
*   失败处理：
    *   [失败类型]后，出现通用失败界面
    *   等待failExitTime自动退出，或点击按钮提前退出
    *   传送到[表名]的ExitScenePosWhileFail
```

**场景规格句式：**
```
*   战斗场地规格：
    *   主体大小为边长[X]m的[形状]区域
    *   中间有[N]根柱子作为掩体
    *   [其他地形特征描述]
```

## 注意事项

- 关卡文档正文统一使用无序列表，不使用编号列表
- Boss技能设计部分的参考视频使用B站链接+精准空降时间戳
- 涉及FC已有功能时，标注「沿用FC的[功能名]逻辑」而非重新描述
- 场景规格必须给出量化数值（面积/尺寸/直径），不可模糊描述
- 演出Sequencer需标注是否包含镜头和怪物动作，以及大致时长
- 配置表中Boss的BirthSN、SceneSN等关联字段必须说明关联关系
- 多人副本必须说明掉线后的副本保留/销毁策略
- Boss技能的预警方式需统一颜色编码规则（如：紫色=通用大招预警，金色=特殊大招预警）
- 引擎资产命名需遵循项目规范（GA_Pal_/GE_/BP_/NS_CommonSkill_/ANIM_）
- 标注「暂不开发」的功能需保留在文档中但加标记，便于后续迭代
