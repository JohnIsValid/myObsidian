## 一、核心原则

1. **按资源类型拆分**：美术需求分为四类——动画、特效、角色原画、场景原画。每类使用各自独立的需求表格式。
2. **模型需求不单列**：所有模型资源均从原画流程开始，在原画需求中体现，不单独开模型需求表。原画需求产出后由美术侧自行拆分建模任务。
3. **格式对齐实际工作表**：每类需求的字段必须与项目实际使用的 Excel 需求表完全一致，因为美术同事直接在该表中跟进状态和排期。
4. **从设计中提取**：所有需求条目必须能追溯到设计方案中的具体描述，不凭空编造美术需求。

---

## 二、资源类型识别

拿到设计方案后，逐条扫描所有与美术表现相关的描述，按以下规则归类：

| 设计内容 | 资源类型 | 典型场景 |
|----------|----------|----------|
| 角色/怪物/帕鲁的动作描述 | **动画需求** | 攻击、受击、待机、移动、技能释放、交互动作、坐骑动作 |
| 粒子效果、光效、打击反馈、环境氛围 | **特效需求** | 技能特效、环境特效、状态特效、UI 特效 |
| 新角色/怪物/帕鲁的外观设计 | **角色原画** | 新帕鲁设计、NPC 外观、Boss 形象 |
| 新场景物件/建筑/道具/装置的外观设计 | **场景原画** | 交互装置、破坏物、玩法入口、场景装饰 |

> 如果一条设计内容同时涉及多种类型（如"Boss 跳砸攻击，落地产生冲击波特效"），拆为两条：一条动画需求（跳砸动作）+ 一条特效需求（冲击波特效）。

## 三、工作流程

### Step 1: 提取美术相关内容

从设计方案中逐条提取所有需要美术制作的内容：
- 明确描述了外观、动作、特效的段落
- 涉及新资源制作（而非复用已有资源）的内容
- 隐含美术需求的内容（如"玩家靠近时物件发光" → 特效需求）

### Step 2: 分类并编写需求条目

将提取的内容按四类资源分组，为每条需求填写对应格式的完整字段。

每类需求的字段定义和格式模板见 `references/` 目录（在编写前必须读取对应的参考文件）：
- 动画需求 → 读取 `references/animation-format.md`
- 特效需求 → 读取 `references/vfx-format.md`
- 角色原画 / 场景原画 → 读取 `references/concept-art-format.md`

### Step 3: 在对话中输出 Markdown 需求表

按以下结构在对话中展示需求内容（便于策划即时审阅和修改）：

```markdown
## 美术需求

### 一、动画需求
（按 references/animation-format.md 格式输出需求表）

### 二、特效需求
（按 references/vfx-format.md 格式输出需求表）

### 三、原画需求
#### 3.1 角色原画
（按 references/concept-art-format.md 格式输出需求表）
#### 3.2 场景原画
（按 references/concept-art-format.md 格式输出需求表）
```

如某类无对应需求则省略该章节，不输出空表。

### Step 4: 导出 Excel 文件（默认执行）

在 Markdown 表格展示完毕后，**自动**将需求数据写入 Excel 文件。每类需求保存为独立的标签页，空类别不创建标签页。

**操作步骤**：

1. 将所有需求条目组织为以下 JSON 结构，写入一个临时 `.json` 文件：

```json
{
  "feature_name": "功能名称",
  "animation": [
    { "版本": "...", "优先级": "...", "动画类型": "动画", "动画中文名称": "...", "动画资源命名": "...", "备注": "...", "动画时长": "...", "是否循环": "...", "连接动作": "...", "提需策划": "..." }
  ],
  "vfx": [
    { "需求名": "...", "优先级": "...", "版本": "...", "状态": "未开始", "需求描述": "...", "最大视距": "...", "是否循环": "...", "持续时长": "...", "特效资产命名": "...", "资产上传路径": "...", "策划": "..." }
  ],
  "character_concept": [
    { "版本": "...", "需求名": "...", "分类": "角色", "优先级": "...", "需求描述": "...", "参考图片": "...", "策划": "...", "状态": "未开始" }
  ],
  "scene_concept": [
    { "版本": "...", "需求名": "...", "分类": "大世界", "优先级": "...", "需求描述": "...", "参考图片": "...", "策划": "...", "状态": "未开始" }
  ]
}
```

> JSON 中每个对象的 key 必须与 Excel 表头完全一致。无数据的类别使用空数组 `[]`。

2. 调用脚本生成 Excel：

```bash
python <skill_path>/scripts/write_art_excel.py <json_path> <output_xlsx_path>
```

- `<output_xlsx_path>` 默认保存到 `~/user/lbworkspace/美术需求_<feature_name>.xlsx`（遵循 `design-conventions` §七 的文件输出约定）
- 如用户指定了输出路径则使用用户指定的路径

3. 告知用户 Excel 文件的完整保存路径和工作区位置。

**Excel 文件结构**：

| 标签页名 | 对应 JSON key | 源格式 |
|----------|--------------|--------|
| 动画需求 | `animation` | PW-动作 |
| 特效需求 | `vfx` | PW-特效（新） |
| 角色原画 | `character_concept` | PW-场景原画（新） |
| 场景原画 | `scene_concept` | PW-场景原画（新） |

### 关于策划姓名和版本

- `提需策划` / `策划` 字段：如果已知策划姓名则填入，否则填 `[策划姓名]` 由策划本人替换
- `版本` 字段：由策划指定目标版本。未指定时填 `[目标版本]` 由策划补充。格式可以是 `6月版本` 或 `6/15版本`

## 四、通用填写指引

### 优先级

| 等级 | 含义 |
|------|------|
| P0 | 当前版本必须完成，阻塞功能上线 |
| P1 | 当前版本需要，可临时降级处理 |
| P2 | 下个版本完成即可 |

优先级的判断依据：该美术资源是否阻塞功能的核心流程。核心战斗动作/特效通常为 P0，辅助表现和锦上添花的效果为 P1-P2。

### 需求描述

- 具体到美术人员可直接执行，避免"做个好看的特效"这类模糊描述
- 描述物理特征时标注尺寸或与已知物体的比例关系
- 描述动态效果时标注时长、节奏、关键帧
- 有多个状态的资源分别描述每个状态的表现

### 参考资料

- 动作参考：优先提供视频链接（B 站、Pinterest），辅以文字姿态描述
- 特效参考：提供参考图片路径或视频链接
- 原画参考：提供参考图片路径、风格关键词
- 当策划未提供参考时，使用 `📌 【策划补图/补视频】` 占位

### 资源命名规范

| 类型 | 格式 | 示例 |
|------|------|------|
| 动画 | `ANIM_[对象名]_[动作名]` | `ANIM_GrassPanda_MeleeSkill_Start` |
| 特效 | `NS_[功能名]_[效果名]` | `NS_SphinxAltar_Loop` |

路径以 `Project\Content\` 开头，按 UE 项目结构组织。命名中对象名使用英文，动作名使用英文驼峰。

## 五、文件结构说明

```
art-requirement/
├── SKILL.md                          ← 本文件
├── scripts/
│   └── write_art_excel.py            ← Excel 写入脚本（Step 4 调用）
└── references/
    ├── animation-format.md           ← 动画需求表格式（源自 PW-动作）
    ├── vfx-format.md                 ← 特效需求表格式（源自 PW-特效（新））
    └── concept-art-format.md         ← 原画需求表格式（源自 PW-场景原画（新））
```

- **references/**：字段定义表、完整示例行、填写注意事项。Step 2 编写需求前读取。
- **scripts/write_art_excel.py**：接收 JSON 数据，生成带样式的 Excel 文件（表头着色、列宽自适应、冻结首行、自动筛选）。Step 4 自动调用，无需手动执行。依赖 `openpyxl`。
