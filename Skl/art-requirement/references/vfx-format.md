# 特效需求表格式

> 源自项目实际使用的 PW-特效（新）.xlsx（大世界特效 Sheet）。

## 字段定义

| 序号 | 字段名 | 必填 | 说明 |
|------|--------|------|------|
| 1 | 需求指派 | 否 | 指定审核人或关联人，格式 `@姓名` |
| 2 | 需求名 | 是 | 简明描述特效内容，如 `跟随毛老爹-延时浆果` |
| 3 | 优先级 | 是 | `P0` / `P1` / `P2` |
| 4 | 版本 | 是 | 目标版本，如 `5月版本`、`6月版本` |
| 5 | 状态 | 否 | 策划提需时填 `未开始`，后续由美术更新 |
| 6 | 需求描述 | 是 | **核心字段**：详细描述特效的视觉表现、颜色、动态、范围。这是美术制作的主要依据 |
| 7 | 参考图片/视频 | 否 | 参考图片路径（多张用逗号分隔）或视频文件路径 |
| 8 | 参考链接 | 否 | Pinterest / B 站等在线参考链接 |
| 9 | 帕鲁资产位置 | 否 | 需要搬运已有资产时填写源路径 |
| 10 | 最大视距 | 是 | 特效可见的最大距离（米），常见值：`50` / `100` / `200` |
| 11 | 是否循环 | 是 | `循环` / `不循环` |
| 12 | 持续时长 | 是 | 不循环特效必填，如 `1s`、`2s`。循环特效可留空 |
| 13 | 特效资产命名 | 是 | `NS_[功能名]_[效果名]`，英文驼峰 |
| 14 | 资产上传路径 | 是 | UE 项目路径，如 `Project\Content\Effect\Particle\Pal\OpenWorld` |
| 15 | 策划 | 是 | 提需策划姓名 |
| 16 | 备注 | 否 | 补充说明，或关联的父记录/工单号 |

## 输出格式

使用 Markdown 表格，列顺序与上方一致。`状态` 统一填 `未开始`。

```markdown
| 需求名 | 优先级 | 版本 | 状态 | 需求描述 | 参考链接 | 最大视距 | 是否循环 | 持续时长 | 特效资产命名 | 资产上传路径 | 策划 | 备注 |
|--------|--------|------|------|----------|----------|----------|----------|----------|-------------|-------------|------|------|
| 祭坛底座特效 | P0 | 6月版本 | 未开始 | 未解答状态蓝色光效，符文微弱脉动 | | 100 | 循环 | | NS_SphinxAltar_Loop | Project\Content\Effect\Particle\Pal\OpenWorld | 张三 | |
| 祭坛判定特效 | P0 | 6月版本 | 未开始 | 光芒增强+判定光环，光环向外扩散 | | 50 | 不循环 | 1s | NS_SphinxAltar_Judge | Project\Content\Effect\Particle\Pal\OpenWorld | 张三 | |
```

## 填写注意事项

1. **最大视距**：影响特效的 LOD 和性能开销。有200，150，100，50，20这几个档位。大世界环境特效通常 200和150，角色和技能特效通常100，不重要的可以50和20
2. **需求描述写法**：描述颜色、形态、动态变化过程。好的描述："柔和的暖黄色发光光圈包裹着浆果"。差的描述："一个发光效果"
3. **成组特效**：同一功能的多个状态特效应成组排列并统一命名前缀，如 `NS_SphinxAltar_Loop` / `NS_SphinxAltar_Judge` / `NS_SphinxAltar_Correct` / `NS_SphinxAltar_Wrong`
4. **循环与时长**：循环特效持续时长可留空（由程序控制开关）；不循环特效必须标注时长
