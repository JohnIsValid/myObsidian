# 原画需求表格式

> 源自项目实际使用的 PW-场景原画（新）.xlsx。角色原画和场景原画使用相同的表格式，分两个章节输出。
> 所有模型需求均从原画开始，不单独提模型需求表。

## 字段定义

| 序号 | 字段名 | 必填 | 说明 |
|------|--------|------|------|
| 1 | 需求指派 | 否 | 指定审核人或关联人，格式 `@姓名` |
| 2 | 版本 | 是 | 目标版本，如 `5月版本`、`6月版本` |
| 3 | 状态 | 否 | 策划提需时填 `未开始`，后续由美术更新 |
| 4 | 需求名 | 是 | 简明名称，如 `大世界帐篷内行军床`、`续时浆果` |
| 5 | 分类 | 是 | 所属场景/功能分类，如 `大世界`、`主线关卡`、`副本场景`、`角色` |
| 6 | 优先级 | 是 | `P0` / `P1` / `P2` |
| 7 | 需求描述 | 是 | **核心字段**：详细描述外观、尺寸、材质、风格、用途。含多个状态时分别描述 |
| 8 | 参考图片 | 否 | 参考图片路径，多张用逗号分隔。无图时用 `📌 【策划补图】` |
| 9 | 需求文档 | 否 | 关联的需求文档链接 |
| 10 | 策划 | 是 | 提需策划姓名 |
| 11 | 制作人 | 否 | 策划提需时留空，由主管分配 |
| 12 | 开始时间 | 否 | 策划提需时留空 |
| 13 | 结束时间 | 否 | 策划提需时留空 |
| 14 | 单号 | 否 | 关联的工单号 |
| 15 | 父记录 | 否 | 关联的父级工单，如 `11289 - 【P2】 - 【大世界模块】玩法入口配置与优化` |

## 输出格式

使用 Markdown 表格。`状态`、`制作人`、`开始/结束时间` 留空。

```markdown
| 版本 | 需求名 | 分类 | 优先级 | 需求描述 | 参考图片 | 需求文档 | 策划 | 备注 |
|------|--------|------|--------|----------|----------|----------|------|------|
| 6月版本 | 隐藏树洞巢穴 | 大世界 | P1 | 被茂密植被和藤蔓遮蔽的大树树洞，内部空间温馨，地面散落浆果。尺寸需容纳1只毛老爹+5只毛掸儿+1个宝箱+1个玩家角色。风格参考潮风群岛森林环境 | 📌 【策划补图】 | 《PW》跟随毛老爹需求 | 陆丹洋 | |
| 6月版本 | 玩法入口-野外BOSS交互建筑 | 大世界 | P0 | 所有野外BOSS附近的统一设施，交互后可查看BOSS信息、切换难度。有【普通难度】和【困难难度】两种状态，通过材质颜色和特效区分 | 📌 【策划补图】 | 野外BOSS调整需求 | 张子华 | |
```

## 角色原画 vs 场景原画的区分

| 类型 | 分类字段填写 | 典型内容 |
|------|------------|----------|
| 角色原画 | `角色`、`帕鲁`、`NPC`、`Boss` | 新帕鲁整体外观、NPC 服装设计、Boss 形象设计 |
| 场景原画 | `大世界`、`主线关卡`、`副本场景` | 交互装置、破坏物、建筑、场景道具、玩法入口 |

两者使用同一套字段格式，仅在输出时分为"角色原画"和"场景原画"两个子章节。

## 填写注意事项

1. **尺寸标注**：必须给出物件尺寸或大致比例。可用厘米/米，或参照已知物体（如"与毛掸儿体型匹配"）。格式示例：`半径：25cm，高：130cm`、`约4m×4m×4m`
2. **多状态描述**：如果物件有多个视觉状态（如普通/困难、开启/关闭、完好/破损），每个状态分别描述外观差异和切换方式
3. **风格关键词**：标注美术风格方向，如"古代文明遗迹"、"野外露营气息"、"符文/魔法"
4. **材质提示**：标注主要材质特征，如"石质"、"木质破旧"、"金属锈蚀"
5. **需求描述结构**：建议按"整体描述 → 关键细节 → 尺寸规格 → 风格/氛围"的顺序组织
