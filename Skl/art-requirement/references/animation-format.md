# 动画需求表格式

> 源自项目实际使用的 PW-动作.xlsx（宠物动作 Sheet）。

## 字段定义

| 序号 | 字段名 | 必填 | 说明 |
|------|--------|------|------|
| 1 | 需求指派 | 否 | 指定审核人或关联人，格式 `@姓名` |
| 2 | 版本 | 是 | 目标版本，如 `5/24版本`、`6月版本` |
| 3 | 优先级 | 是 | `P0` / `P1` / `P2` |
| 4 | 动画类型 | 是 | 固定填 `动画` |
| 5 | 动画中文名称 | 是 | 简明描述动画内容，如 `叶胖达普攻-起手` |
| 6 | 制作进度 | 否 | 策划提需时留空，由美术填写 |
| 7 | 动画资源命名 | 是 | `ANIM_[对象名]_[动作名]`，英文驼峰 |
| 8 | 备注 | 是 | **核心字段**：详细描述动作表现、姿态、节奏。这是美术制作的主要依据 |
| 9 | 动作参考 | 否 | 参考视频链接或图片路径 |
| 10 | 动画时长 | 是 | 秒为单位，如 `0.66`、`2s`、`3~4s` |
| 11 | 是否循环 | 是 | `循环` / `不循环` |
| 12 | 融合状态 | 否 | 动画融合方式说明 |
| 13 | 连接动作 | 否 | 前置动作名（表示动画衔接关系），如 `Idle`、`Start`、`Action` |
| 14 | 制作美术 | 否 | 策划提需时留空，由主管分配 |
| 15 | 提需策划 | 是 | 提出需求的策划姓名 |
| 16 | 上传路径 | 否 | UE 项目中的资产路径，如 `Project\Content\Character\Monster\Pal\...` |

## 输出格式

使用 Markdown 表格，列顺序与上方一致。策划提需时 `制作进度`、`制作美术` 留空。

```markdown
| 版本 | 优先级 | 动画类型 | 动画中文名称 | 动画资源命名 | 备注 | 动作参考 | 动画时长 | 是否循环 | 连接动作 | 提需策划 |
|------|--------|----------|-------------|-------------|------|----------|----------|----------|----------|----------|
| 6月版本 | P0 | 动画 | 叶胖达普攻-起手 | ANIM_GrassPanda_MeleeSkill_Start | 左手前抬，右手往后缩，身子微侧 | | 0.66s | 不循环 | Idle | 张三 |
| 6月版本 | P0 | 动画 | 叶胖达普攻-蓄力 | ANIM_GrassPanda_MeleeSkill_StartLoop | 保持Start动作，小幅上下晃动保持蓄力 | | 1s | 循环 | Start | 张三 |
| 6月版本 | P0 | 动画 | 叶胖达普攻-攻击 | ANIM_GrassPanda_MeleeSkill_Action | 右手向前冲拳 | | 0.33s | 不循环 | Start | 张三 |
```

## 填写注意事项

1. **动作序列**：同一技能/行为的多段动作应成组排列，通过 `连接动作` 字段标明衔接关系。典型序列：`起手 → 蓄力(Loop) → 攻击 → 持续攻击(Loop) → 结束`
2. **备注写法**：描述具体的身体姿态和动态，不要只写"攻击动作"。好的备注："右手前拍（像拍门一样），拍到前方胸口高度，肚皮做一次抖动"。差的备注："进行攻击"
3. **时长规范**：精确到小数点后两位（秒），如 `0.66`、`0.33`。范围值用 `~` 连接，如 `3~4s`
4. **循环动画**：蓄力、待机、持续攻击等通常为循环；起手、攻击、结束通常为不循环
