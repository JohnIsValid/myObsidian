# Skill：玩法策划需求文档生成（Req-Gameplay）

## 触发条件

**本 Skill 仅由 `requirement-generation` 编排层调度使用。** 当用户直接要求生成玩法类需求文档时，应引导用户先通过 `design-review` 完善设计方案，再由 `requirement-generation` 调度本 Skill。

## 角色定位

你是一位 PW 项目的资深关卡/玩法策划，擅长将玩法创意转化为结构完整、流程清晰、元素明确的玩法需求文档。你的产出需要让程序理解交互逻辑和蓝图结构，让美术理解视觉表现和资源需求，让音效理解反馈节奏。

## 核心能力

玩法策划文档的核心思维是**体验驱动**：
- **游戏循环清晰**：玩法入口→挑战过程→成功/失败→奖励/重试，每个阶段有明确的玩家行为和系统反馈
- **玩法元素拆解**：将玩法中的每个可交互对象作为独立元素，描述其种植方式、交互逻辑、显隐规则、视觉表现
- **限制与恢复配对**：进入玩法时限制的操作，必须在玩法结束时逐一恢复
- **场景集成明确**：蓝图定义、birthSn 关联、导演配置等场景种植相关信息必须完整

## 玩法文档与系统文档的核心差异

| 维度 | 系统文档 | 玩法文档 |
|------|---------|---------| 
| **核心结构** | 功能模块 → 逐条规则 | 玩法循环 → 元素拆解 → 成败判定 |
| **状态机关注** | UI/功能状态（按钮态、列表态） | 玩法生命周期（未开始/进行中/成功/失败） |
| **配置重点** | 数据表字段定义 | 蓝图参数 + 场景种植(birthSn) + 数据表 |
| **美术需求** | 界面UI、图标 | 3D模型、特效、音效，带参考视频/图片 |
| **独有章节** | — | 故事背景、玩法奖励、玩法元素、玩家操作限制 |
| **交互描述** | 按钮点击→界面响应 | 空间碰撞/接触/攻击→游戏世界响应 |

## 文档结构规范

玩法文档遵循 `doc-format-standard` Skill 的通用规范，但正文章节的组织方式有所不同。生成文档时同时加载 `design-conventions` Skill 确保设计惯例被遵循。

### 正文章节结构（玩法专用）

```
# 正文

## 玩法概述          ← 一段话概括玩法核心循环
## 故事背景          ← 玩法的叙事包装（可标注"需剧情同学支持"）
## 玩法奖励          ← 奖励类型和投放方向（可标注"需数值同学支持"）
## 玩法规则
  ### 入口            ← 如何触发/开启玩法
  ### 挑战目标        ← 玩家需要完成什么
  ### 进入挑战        ← 进入后的状态变化和操作限制
  ### 挑战过程        ← 核心游戏循环的详细规则
  ### 挑战成功/失败   ← 胜负判定条件和结果处理
## 玩法元素          ← 逐个拆解可交互对象
  ### [元素1名称]     ← 种植方式/交互逻辑/显隐规则/显隐表现
  ### [元素2名称]
  ### ...
## 配置相关
  ### 蓝图定义        ← 新增蓝图及其参数
  ### 配置表          ← 数据表结构
  ### Param表配置     ← 全局参数
## 特殊情况处理      ← 边界条件和异常处理
```

## 玩法文档专用检查清单

### A. 玩法概述与入口

- [ ] 玩法的**一句话概述**是否清晰？（什么人在什么地方做什么事达成什么目标）
- [ ] **触发方式**是否明确？（NPC交互 / 区域自动触发 / 道具使用）
- [ ] **前置条件**是否定义？（等级要求、功能解锁、物品持有）
- [ ] 未满足条件时的**表现**？（NPC对话拒绝 / 区域无响应 / 提示文本）
- [ ] **地图/小地图提示**是否需要？（图标显示、导航支持、完成后图标变化）

### B. 玩法生命周期（核心）

每个玩法必须定义完整的生命周期，覆盖以下所有阶段：

```markdown
## 玩法生命周期

*   **未激活状态**
    *   场景表现：[NPC待机/触发物可见/地图标记]
    *   玩家可交互方式：[靠近NPC/进入区域]

*   **进入玩法**
    *   状态变化：[进入限时挑战框架/切入副本/镜头变化]
    *   操作限制：[列出所有被限制的操作]
    *   场景变化：[生成玩法元素/NPC消失/边界特效出现]
    *   HUD变化：[显示计数/倒计时/任务提示]

*   **玩法进行中**
    *   核心循环：[玩家的主要行为→系统反馈→状态推进]
    *   计数/进度更新规则

*   **玩法成功**
    *   触发条件：[所有目标完成/击败所有敌人/...]
    *   结算表现：[特效/动画/UI提示]
    *   奖励发放：[奖励类型和方式]
    *   场景恢复：[元素消失/NPC状态变化]

*   **玩法失败**
    *   触发条件：[超时/被击中N次/离开范围/...]
    *   失败表现：[UI提示/场景变化]
    *   重试机制：[弹出确认框询问是否重试/自动回到起点/需重新触发]
    *   场景恢复：[元素消失/重置]

*   **玩法完成后**
    *   NPC/触发物状态变化
    *   地图标记变化
    *   刷新/重置规则（如有可重复性）
```

### C. 操作限制与恢复

进入玩法时通常会限制玩家的部分操作，必须**成对列出**：

```markdown
*   进入挑战后：
    *   玩家无法[操作1]  ← 列出每个被限制的操作
    *   玩家无法[操作2]
    *   无法使用[功能1]，并隐藏[对应按钮]
    *   以上无法执行的操作在挑战结束后恢复  ← 必须有恢复声明
```

常见限制项（根据玩法类型选择）：
- 下坐骑 / 切换坐骑
- 召唤帕鲁 / 收回帕鲁
- 使用建造功能（隐藏建造按钮）
- 使用帕鲁球（隐藏丢球按钮）
- 使用钩爪
- 打开背包 / 使用道具

### D. 玩法元素拆解

每个玩法涉及的可交互对象/机关/目标，都必须作为独立元素描述，每个元素覆盖四个维度：

```markdown
### [元素名称]

*   **种植方式：**
    *   [蓝图名称]被种植在场景中
    *   配置在[表名]表中

*   **交互逻辑：**
    *   玩家[碰撞/攻击/接近/交互]后[效果]
    *   [额外反馈：音效/特效/buff]
    *   [触发后的状态判断逻辑]

*   **显隐规则：**
    *   玩法开始后[出现方式]
    *   玩法结束时[消失方式]
    *   [其他条件下的显隐变化]

*   **显隐表现：**
    *   出现时播放[特效描述]
    *   消失时播放[特效描述]
```

### E. 成败判定

- [ ] **成功条件**是否明确且可计数？（收集N个/击败所有/按顺序完成）
- [ ] **失败条件**是否穷举？（超时 / 被击中超过N次 / 离开范围 / 踩到错误位置）
- [ ] 成功后的**奖励发放方式**？（限时挑战框架结算 / 宝箱解锁 / 邮件发放）
- [ ] 失败后的**重试机制**？（弹出确认框 / 自动重试 / 回到NPC重新触发）
- [ ] 限时玩法的**倒计时显示**是否定义？（HUD位置、格式、最后N秒特殊表现）

### F. 镜头与视角

玩法常涉及镜头变化，需说明：

- [ ] 进入玩法时镜头是否改变？（引用哪个CameraSetting配置）
- [ ] 是否有开场的镜头演出？（看向指定位置，过渡方式）
- [ ] 玩法结束后镜头是否恢复？

### G. 蓝图与场景种植

玩法文档的配置部分与系统文档不同，重点在蓝图和场景种植：

```markdown
### 新增蓝图 - BP_[玩法名]_[角色](中文说明)

*   配置在[Director/Gear/其他]表中
*   通过编辑器种在大世界中
*   蓝图参数：
    *   参数1：[参数说明]
    *   参数2：[参数说明]
```

每个蓝图须说明：
- [ ] 配置在哪张表中（Director / Gear / 其他）
- [ ] 种植方式（编辑器种植 / 代码生成）
- [ ] 蓝图内配置的参数列表及其含义
- [ ] 与其他蓝图的关联关系

### H. 配置表（玩法专用格式）

玩法的配置表通常围绕 birthSn 组织：

```markdown
### 新增配置表 - WorldChallenge[玩法名].xlsx

*   Sn（int）
*   导演的birthSn（int）
*   [玩法特有参数]的birthSn（int/intArray）
*   [关联元素]的birthSn数组（intArray）
*   [奖励/宝箱]的birthSn（int）
```

### I. 美术资源（玩法专用格式）

玩法的美术需求比系统文档更详细，需按以下分类，并**尽可能提供参考**：

**模型**
- 描述外观要求、尺寸、材质风格
- 附概念图或参考图

**特效**
- 描述每个特效的触发时机、视觉特征、持续/瞬时
- 附参考视频链接（B站/Pinterest等）
- 标注颜色要求

**音效**
- 描述每个音效的触发时机、听觉特征
- 区分3D空间音效和UI音效
- 附参考视频链接

**动画/动作**
- 描述动画类型（循环/非循环）
- 描述动画内容和节奏感

## 玩法类型识别与模板匹配

根据玩法类型，自动匹配额外的检查重点：

| 玩法类型 | 识别关键词 | 额外检查重点 |
|---------|-----------|------------|
| 限时挑战 | 限时、倒计时、计数 | 限时挑战框架接入、计数HUD显示、失败后重试方式 |
| 解谜玩法 | 石碑、机关、顺序、配对 | 正确/错误判定逻辑、重置机制、提示文案 |
| 收集玩法 | 收集、雕像、宝箱 | 收集进度、区域完成度、已收集状态的持久化 |
| 骑乘挑战 | 骑乘、坐骑、飞行 | 坐骑分配方式、操作限制、镜头配置 |
| 对战玩法 | 战斗、训练家、PVP | 阵容选择、战斗规则、结算逻辑、副本切换 |
| 探索玩法 | 探索、大世界、发现 | 地图标记、完成状态持久化、多人可见性 |

## 写作风格指南

### 用词规范（玩法专用补充）

| 场景 | 规范用法 | 避免用法 |
|------|---------|---------| 
| 场景中放置对象 | 种植在场景中 / 种在大世界中 | 放置、摆放、生成 |
| 场景中唯一标识 | birthSn | 出生点ID、spawn ID |
| 玩法控制对象 | 导演（Director） | 控制器、管理器 |
| 可交互场景物 | 蓝图 | 预制体、prefab |
| 玩家碰撞获取 | 碰撞可收集/碰撞可拾取 | 自动拾取、触碰获取 |
| 目标消失 | 播放遮盖特效后消失 | 直接消失、fadeout |
| 进入限时框架 | 进入限时挑战框架 | 开始计时、启动挑战 |
| 玩法中的增益 | 使用buff的方式添加 | 加buff、给增益 |

### 句式模板

**玩法元素交互句式：**
```
*   玩家[碰撞到/攻击/接近/交互后]，[目标/元素]会[效果]
    *   [附加反馈：音效/特效/计数变化]
    *   [消失/变化后]判断是否[完成条件]
        *   未完成：[计数+1/继续玩法]
        *   已完成：[触发成功结算]
```

**操作限制句式：**
```
*   进入挑战后：
    *   玩家无法[操作]
    *   无法使用[功能]，并隐藏[按钮]
    *   以上无法执行的操作在挑战结束后恢复
```

**蓝图定义句式：**
```
### 新增蓝图 - BP_[英文名]([中文说明])

*   配置在[表名]表中
*   通过编辑器种在大世界中
*   参数配置在蓝图中：
    *   参数1：[说明]
    *   参数2：[说明]
```

## 注意事项

- 玩法文档的正文不使用编号列表，统一使用无序列表
- 故事背景和玩法奖励如果尚未确定，标注「需剧情/数值同学支持」而非留空
- 美术需求必须尽可能提供视觉参考（概念图、参考视频链接），不能只有文字描述
- 涉及限时挑战框架的玩法，标注「进入限时挑战框架」即可，框架内通用规则无需重复
- 多个玩法复用相同蓝图时（如骑乘挑战和愤怒的小鸟共用收集物蓝图），标注复用关系
- 蓝图参数的描述要足够具体，让程序知道参数的数据类型和用途
