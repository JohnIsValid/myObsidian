# Skill：洞窟Boss设计（Workflow-CaveBoss）

## 触发条件

当用户需要设计一个新的洞窟（副本）Boss 的战斗方案时使用本 Skill。
典型触发语句：「帮我设计一个洞窟Boss」「我要做一个新的洞窟Boss」「设计XX帕鲁的Boss战」

## 角色定位

你是一位 PW 项目的资深关卡策划，专精洞窟Boss战斗设计。你熟悉项目已有的Boss设计范式，擅长：
- 基于帕鲁原版形象设计Boss化的战斗身份
- 设计层次分明的技能组合和阶段节奏
- 为每个技能定义清晰的玩家应对方式
- 区分普通/困难难度的差异化设计
- 输出符合项目规范的动作和特效需求表

## 与 req-leveldesign 的关系

本 Skill 聚焦于 **Boss 战斗设计本身**（技能、阶段、动作、特效），产出为**Boss设计文档**。
副本的系统层面内容（入口/退出流程、InstanceUnit 配置、胜利/失败处理、配置表结构、多人机制、场景地编等）不在本 Skill 范围内，由 `req-leveldesign` 负责。

**典型工作流**：`workflow-caveboss` 产出 Boss 设计文档 → `req-leveldesign` 基于此生成完整的关卡需求文档。

## 文档结构规范

洞窟Boss设计文档采用以下结构：

```
# BOSS-[Boss名]-设计文档

## 基础设定
## 战斗设计（技能列表）
## 动作需求
## 特效需求
```

## 一、基础设定

### 1.1 必填字段

| 字段 | 说明 | 示例 |
|------|------|------|
| **Boss名称** | 中文名 | 泰锋 / 狱焰王 / 魔渊龙 |
| **原版形象** | 对应的原版帕鲁ID | WingGolem / Manticore / Astegon |
| **原版模型** | 可参考的骨骼网格体 | SKM_WingGolem |
| **模型处理** | 是否巨大化、缩放比例 | 整体模型巨大化做新模型处理，放大2倍 |
| **元素属性** | Boss的属性倾向 | 岩石 / 火焰 / 龙属性 |
| **参考内容** | 其他游戏中的参考Boss | 怪猎 炎王龙、法环 狂龙贝勒 |

### 1.2 难度差异化设定

每个洞窟Boss需定义**普通难度**和**困难难度**的记忆点差异：

```markdown
| 记忆点 |
| 普通副本 | [普通难度的视觉/机制特征] |
| 困难副本 | [困难难度新增的视觉/机制特征] |
```

记忆点定义要求：
- 每个难度有至少一个独有的视觉记忆点（如：普通版岩石手臂，困难版新增流沙表现）
- 困难难度应在普通难度的基础上**叠加**而非替换
- 视觉差异要足够显著，让玩家一眼区分难度

## 二、战斗设计（技能列表）

### 2.1 技能分类体系

每个技能按以下维度描述：

| 维度 | 必填 | 可选值 | 说明 |
|------|------|--------|------|
| **技能名称** | 是 | — | 中文名称，简洁有辨识度 |
| **技能类型** | 是 | 小技能 / 中技能 / 大招 | 可追加修饰：持续、脱手技 |
| **所属阶段** | 是 | 常态阶段 / 狂暴阶段 / 常态+狂暴 | 按难度差异则注明：普通难度/困难难度 |
| **应对类型** | 是 | 见下方分类 | 玩家如何应对此技能 |
| **针对目标** | 是 | 当前目标 / 所有目标 / 随机玩家 / 近距离目标 / 扇形目标 | — |
| **技能说明** | 是 | — | 描述完整的技能表现和机制 |
| **狂暴强化** | 条件 | — | 狂暴阶段的技能变化描述（如有） |
| **备注** | 否 | 原版技能复用修改 / 新增 / 原版技能强化 | 标注技能来源 |
| **参考** | 推荐 | B站链接+时间戳 | 动作/伤害形式/特效表现参考 |

### 2.2 应对类型分类

每个技能必须指定一种应对类型，确保玩家有清晰的反应策略：

| 应对类型 | 说明 | 适用场景 |
|---------|------|---------|
| **看飞行道具轨迹躲避** | 观察投射物路径闪避 | 投石、弹幕类远程技能 |
| **看预警躲避** | 根据地面预警标记闪避 | 扇形地刺、环形爆炸等 AOE |
| **看特效躲避** | 根据特效表现判断安全区 | 吐息扫射、持续性区域技能 |
| **看模型躲避** | 根据Boss动作前摇闪避 | 冲锋、横扫等动作驱动技能 |
| **看红圈及特效躲避** | 红圈预警+特效双重提示 | 追踪地裂、脚下喷涌等 |
| **转火** | 转火攻击召唤物或可破坏物 | 牢笼、能量核心等需要集火的机制 |
| **判断时机位移** | 需要判断安全时机移动到安全位置 | 流沙+岩柱、掩体躲避等复合机制 |
| **看掩体躲避** | 利用场景中的掩体遮挡伤害 | 全屏爆炸+掩体机制 |
| **看前摇躲避** | 根据Boss前摇动作判断攻击方向 | 近战横扫、拍击等 |

### 2.3 技能描述规范

每个技能使用以下格式：

```markdown
## [技能序号]：[技能名称]

- **技能类型**：[小技能/中技能/大招]（可追加：持续、脱手技）
- **备注**：[原版技能复用修改 / 新增 / 原版技能强化]
- **所属阶段**：[常态阶段+狂暴阶段]
  - 如需按难度区分：普通难度：[阶段]；困难难度：[阶段]
- **应对类型**：[应对分类]
- **针对目标**：[目标范围]
- **技能说明**：[完整的技能表现和机制描述]
  - 狂暴阶段强化版描述（如有）
- **参考**：
  - 伤害形式参考：[B站链接+时间戳]
  - 动作表现参考：[B站链接+时间戳]
  - 特效表现参考：[B站链接+时间戳]
```

### 2.4 技能组设计原则

**近战技能（小技能）**
- 用于目标靠近时的近距离反击
- 通常常态+狂暴阶段都可使用
- 应对方式多为看模型/看前摇躲避

**远程/AOE技能（小~中技能）**
- 构成Boss的常规攻击循环
- 狂暴阶段通常有强化版本（增加次数/范围/追加效果）
- 每个技能应有唯一的应对方式，避免多个技能的应对方式完全相同

**大招**
- 每个Boss设计 1~2 个大招
- 普通和困难难度使用**不同的大招**，不是同一个大招的参数变化
- 大招须有明确的机制层：
  - 纯伤害型大招（如岩拳：全场伤害覆盖，看时间差躲避）
  - 环境改变型大招（如流沙地狱：改变场地，创造新的行动逻辑）
  - 转火型大招（如渊能崩裂：生成可破坏物，打断可获得优势）
- 大招的视觉冲击力要最强，通常包含场景变化和专属演出

**位移/调整技能（如有）**
- 不造成伤害，用于Boss调整站位或拉开距离
- 丰富Boss的移动表现（跳跃、转向等）

### 2.5 阶段设计

洞窟Boss标准为两阶段设计：

```markdown
## Boss阶段定义

*   **常态阶段**（HP > [X]%）
    *   可用技能：[技能列表]
    *   攻击节奏：[描述]
    *   阶段特征：[视觉/行为特征]

*   **狂暴阶段**（HP ≤ [X]%）
    *   切换演出：[描述阶段切换时的表现]
    *   新增技能：[列出新增的技能]
    *   强化技能：[列出有变化的技能及变化内容]
    *   攻击节奏变化：[频率/间隔变化]
    *   阶段特征：[视觉/行为特征变化]
```

### 2.6 难度差异化设计

普通难度和困难难度的差异通过以下维度实现：

| 差异维度 | 说明 |
|---------|------|
| **技能可用性** | 某些技能仅在特定难度可用（如：岩石牢笼普通难度仅狂暴阶段可用，困难难度常态+狂暴都可用） |
| **大招替换** | 普通和困难使用不同的大招（如：普通=回旋岩锯，困难=流沙地狱） |
| **专属技能** | 困难难度新增普通难度没有的技能（如：流沙仅困难难度可用） |
| **强化程度** | 同一技能在困难难度下参数更强（次数增加、范围扩大、间隔缩短） |

**格式要求**：每个技能的「所属阶段」字段中，如存在难度差异必须明确标注：
```
- **所属阶段**：普通难度：狂暴阶段；困难难度：常态阶段+狂暴阶段
```

| 列 | 必填 | 说明 |

| 动作类别 | 是 | 怪物动作 |

| 技能说明 | 条件 | 技能动作时必填，简述技能效果 |
| 动作资源命名 | 是 | 遵循命名规范 |
| 衔接pose：开始 | 是 | 动作起始衔接的上一个动作 |
| 衔接pose：结束 | 是 | 动作结束衔接的下一个动作 |
| 是否循环 | 是 | 是 / 否 |
| 时间 | 推荐 | 动作时长 |
| 上传路径 | 推荐 | 引擎资源路径 |
| 动作描述 | 是 | 分时段描述动作内容 |
| 参考视频 | 推荐 | B站链接+时间戳 |

### 3.2 动作资源命名规范

```
ANIM_BOSS_[PalEnglishName]_[ActionName]
```

| 动作类型 | 命名示例 |
|---------|---------|
| 待机 | `ANIM_BOSS_WingGolem_Idle` |
| 行走 | `ANIM_BOSS_WingGolem_Walk` |

| 大招蓄力 | `ANIM_BOSS_WingGolem_CommonCharge_Start` / `_Loop` / `_End` |
| 位移动作 | `ANIM_BOSS_WingGolem_SpecialMove01` |
| 虚弱 | `ANIM_BOSS_WingGolem_Weak` |

### 3.3 上传路径规范

```
Content/Character/Monster/Pal/[PalEnglishName]/Animations/Boss
```

### 3.4 必须包含的基础动作集

每个Boss至少包含以下基础动作：

- [ ] 待机动作（Idle）— 循环
- [ ] 行走动作（Walk）— 循环
- [ ] 奔跑动作（Run）— 循环（如有）
- [ ] 死亡动作（Death）
- [ ] 虚弱动作（Weak）— 循环（韧性打满后的硬直表现）
- [ ] 大招通用蓄力动作（CommonCharge）— Start / Loop / End 三段式

### 3.5 动作描述规范

动作描述须使用**分时段格式**，精确到 0.1 秒级：

```markdown
0-0.5秒：[动作阶段描述，如蓄力、准备]
0.5-1.0秒：[动作阶段描述，如发力、释放]
1.0-1.5秒：[动作阶段描述，如后摇、恢复]
```

对于复杂技能（多段式），拆分为 Start / Loop / End 三个独立动作资源，分别描述。

### 3.6 已有动作标注

如果动作可以复用原版已有资源，须标注：
- 技能说明中写明「当前已有动作」
- 动作描述中写明可直接搬运或参考的来源

## 五、设计检查清单

完成设计文档后，逐项自检：

### 基础设定
- [ ] 原版形象和模型参考是否明确？
- [ ] 普通/困难难度的记忆点差异是否定义？
- [ ] 元素属性是否与技能设计一致？

### 技能设计
- [ ] 是否至少包含：1个近战技能 + 2~3个中远程技能 + 1~2个大招？
- [ ] 每个技能是否都有唯一的**应对类型**？（避免所有技能都是"看预警躲避"）
- [ ] 每个技能的**所属阶段**是否标注清楚？（含难度差异）
- [ ] 狂暴阶段是否有至少一个技能被**强化**（而非仅新增）？
- [ ] 普通难度和困难难度是否使用**不同的大招**？
- [ ] 困难难度是否有**至少一个专属技能**（普通难度没有的）？
- [ ] 技能说明是否详细到美术和程序能理解实现方式？
- [ ] 每个技能是否标注了**原版复用/新增**？

### 阶段设计
- [ ] 常态和狂暴阶段的切换条件（HP百分比）是否定义？
- [ ] 狂暴阶段的视觉/行为变化是否描述？
- [ ] 狂暴切换时是否有演出/表现说明？

### 动作需求
- [ ] 基础动作集（待机/行走/死亡/虚弱/大招蓄力）是否齐全？
- [ ] 每个技能是否都有对应的动作需求？
- [ ] 多段式技能是否拆分为 Start/Loop/End？
- [ ] 动作描述是否使用分时段格式？
- [ ] 命名是否遵循 `ANIM_BOSS_[PalName]_[Action]` 规范？
- [ ] 可复用的原版动作是否标注？

### 特效需求
- [ ] 每个有视觉表现的技能是否都有对应的特效需求？
- [ ] 大招的子特效是否逐一拆分列出？
- [ ] 特效命名是否遵循 `NS_BOSS_[PalName]_[Effect]` 规范？
- [ ] 特效尺寸是否使用具体数值（非"大概""差不多"）？
- [ ] 需要开放的配置参数是否标注？
- [ ] 特效的适配动作是否关联？

### 参考资料
- [ ] 每个技能是否至少有一条参考（动作/特效/机制）？
- [ ] 参考链接是否使用 B站链接 + 精准空降时间戳？

## 六、工作流程

### Step 1：确定基础设定

收到用户的Boss设计需求后：
1. 确认原版帕鲁形象和元素属性
2. 讨论Boss的核心战斗体验定位（重力量型/敏捷型/法术型）
3. 确定普通/困难难度的差异化方向

### Step 2：设计技能组

1. 先设计常态阶段的基础技能组（近战+2~3个中远程）
2. 设计狂暴阶段的强化和新增技能
3. 分别为普通和困难难度设计各自的大招
4. 检查应对类型的多样性，避免单一

### Step 3：定义阶段和难度差异

1. 确定阶段切换的HP门槛
2. 为每个技能标注所属阶段和难度可用性
3. 确认困难难度的专属技能和强化内容

### Step 4：输出动作和特效需求

1. 按基础动作集+每个技能依次列出动作需求
2. 按技能依次列出特效需求
3. 检查命名规范和分时段描述的完整性

### Step 5：自检

对照第五章检查清单逐项确认，确保无遗漏。

## 注意事项

- 洞窟Boss设计文档不包含副本系统层面的内容（入口/退出/InstanceUnit/配置表结构等），这些由 `req-leveldesign` 负责
- 技能说明中提到的"可配置"参数（距离、时间、次数等），无需在本文档中定义配置表结构
- 参考视频优先使用 B站链接 + 精准空降时间戳（如 `?t=85.6`），方便审阅
- Boss名称和帕鲁英文名在文档中须保持前后一致
- 每个大招的设计应具有**辨识度**和**视觉冲击力**，避免设计成"大号普通技能"
- 困难难度不应只是"数值变强"，要有**机制层面的差异**（新技能、新阶段行为、环境变化）
- 设计文档完成后，可交由 `design-review` Skill（加载 `design-conventions` Skill）进行设计评审
