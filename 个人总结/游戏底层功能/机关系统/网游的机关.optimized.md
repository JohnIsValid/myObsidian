# 网游的机关系统

## 特殊注意

### 前后端职责区分

- 机关需要区分前端表现与后端行为。
- 前端表现：
  - 火焰特效。
- 后端行为：
  - 伤害计算。
  - 伤害范围判定。

### 虚幻引擎中的客户端生成判断

- 在虚幻引擎中，需要额外判断相关逻辑是否只在客户端生成。
- 示例：
  - `TimeLine` 如果不进行客户端判断，可能会同时在 DS 上运行逻辑，从而产生较大的性能开销。

## 机关的唯一 ID

- 所有机关都必须拥有唯一 ID。
- 唯一 ID 是定位机关的主要方式。
- 一般命名格式为：
  - `机关名称_序列ID_地图ID`
- 示例：
  - `RedTrigger_104_10031`

## 机关的隶属关系

- 机关的隶属关系可以分为以下几类：
  - **地图公有**
  - **玩家私有**
  - **队伍私有**
  - **帮会私有**

### 地图公有

- 属于当前地图的数据。
- 只要玩家处于这张地图上，就都可以看到该机关或相关数据。

### 玩家私有

- 属于玩家自己的数据。
- 其他玩家不可见。

### 队伍私有

- 属于队伍内部的数据。
- 非队伍内玩家不可见。
- 只有在队伍存在时，才会有这类数据。

### 帮会私有

- 属于帮会内部的数据。
- 非帮会内部玩家不可见。
- 只有在帮会存在时，才会有这类数据。

## 机关的状态

### 状态机制

- 机关通常是有状态的。
- 机关可以拥有数量不等的状态。
- 机关的不同表现通常通过状态切换实现。
- 不同状态下，机关会有不同的外观表现。
- 机关切换状态时，可以播放状态切换动画。
- 可以通过配置决定状态变化的时机：
  - 在切换动画播放前改变状态。
  - 在切换动画播放后改变状态。

### 状态下的交互与行为

- 机关在每个状态下，都可以拥有不同的交互方式，并由交互触发对应行为。
- 机关行为包括但不限于：
  - 改变自身状态。
  - 改变其他机关状态。
  - 改变玩家属性。
  - 产生瞬间范围伤害。

## 机关如何引用其他机关或单位

### 常见配置方式

- 机关配置通常有三种方式：
  - 在实例中配置。
  - 在表中配置。
  - 同时在表和实例中配置。

### 使用唯一 ID 建立关联

- 引用其他机关时，通常会使用前文提到的唯一 ID。
- 策划可以通过配置唯一 ID，将机关之间建立关联。

### 表与实例结合配置

- 对于唯一 ID 的配置位置，通常可以采用“表 + 实例”结合的方式。
- 表中配置一个代称。
- 实例中将代称与具体唯一 ID 进行绑定。
- 将配置好的一套机关打组为预制体后，即可复用。

## 机关的交互

### 交互形式

- 机关可以被交互。
- 常见交互方式包括：
  - 进入区域。
  - 离开区域。
  - 在指定范围内按 `F`。
  - 在指定范围内按 `E`。
  - 使用不同属性的技能攻击。
  - 使用远程武器射击。
  - 使用魔法攻击。

### 多交互方式支持

- 同一个机关可以支持多种交互方式。
- 示例：
  - 玩家按 `F` 可以按下按钮。
  - 玩家使用远程攻击也可以按下同一个按钮。
