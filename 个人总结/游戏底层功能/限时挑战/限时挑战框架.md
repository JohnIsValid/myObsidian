# 限时挑战框架

## 1. 定义

限时挑战是在限定时间内，引导玩家完成一个或多个目标，并在成功后发放奖励的玩法类型。

## 2. 核心特性

- **时间限制**：挑战有明确倒计时，过程中可根据事件或配置增加/减少剩余时间。
- **多目标支持**：挑战可同时包含一个主目标和多个子目标。
- **阶段流程**：挑战可以拆分为多个阶段，每个阶段拥有独立目标、提示、场景物件或规则。
- **过程反馈**：挑战过程中可播放独立 BGM，并在指定时间点或条件达成时显示 Tips。
- **可退出**：玩家可主动退出挑战。
- **死亡处理**：挑战过程中死亡后，玩家会回到指定原点。

## 3. 目标规则

### 3.1 目标结构

- 同一时间只能存在一个主目标。
- 同一时间可以存在多个子目标。
- 主目标可以根据条件变化。
- 子目标是否必须全部完成，由配置决定。

### 3.2 子目标完成逻辑

子目标可支持以下配置：

- 全部完成后挑战成功。
- 任意一个完成后挑战成功。
- 部分子目标完成后触发失败。
- 子目标只作为额外奖励或辅助提示，不影响挑战成败。

## 4. 成功/失败条件类型

限时挑战既可以是“达到条件后成功”，也可以是“达到条件后失败”。条件类型包括：

| 条件类型 | 说明 | 示例 |
| --- | --- | --- |
| 计时 | 在指定时间内存活、坚持或等待事件结束 | 坚持 60 秒 |
| 计数 | 累计完成指定数量 | 击败 10 个敌人 |
| 倒数 | 从指定数量递减至 0 | 剩余目标数归零 |
| 进度条 | 根据行为推进进度，满/空后触发结果 | 占领进度达到 100% |

## 5. 挑战启动流程

### 5.1 标准启动流程

1. 玩家触发限时挑战。
2. 加载挑战所需物件。
3. 可选：播放开场 Sequence。
4. 可选：黑屏淡入淡出，用于遮盖传送和镜头调整。
5. 将玩家传送到指定地点。
6. 调整玩家朝向，使其看向指定位置。
7. 可选：播放开始前倒计时。
8. 正式开始挑战计时与目标检测。

### 5.2 启动配置要点

- 挑战开始后可将玩家传送到指定地点，并看向指定位置。
- 若存在开始前倒计时，应先完成传送和朝向调整，再进入倒计时。
- 挑战开启后需要加载的指定物件，应在倒计时开始前完成加载。
- 挑战开启前可以使用短暂黑屏遮盖传送和镜头切换。
- 挑战开启前可以播放 Sequence；Sequence 结束后进入黑屏淡入淡出，在淡入淡出期间执行传送，最后进入倒计时。

## 6. 挑战过程表现

- 挑战过程中播放独立 BGM。
- 在指定时间点播放提示 Tips。
- 在指定条件达成时播放提示 Tips。
- 时间增加/减少时，应有清晰的 UI 或音效反馈。
- 主目标变化时，应更新目标提示和追踪信息。

## 7. 结算与失败处理

### 7.1 成功结算

挑战成功后需要：

- 播放醒目的成功提示。
- 告知玩家获得了哪些奖励。
- 发放奖励。
- 清理挑战物件、BGM、目标追踪和临时状态。

### 7.2 失败处理

挑战失败后需要：

- 播放失败提示。
- 询问玩家是否：
  - 回到原点；
  - 重新开始挑战。
- 清理或重置挑战过程中的临时状态。

## 8. 配置建议

一个限时挑战配置建议至少包含：

- 挑战 ID
- 挑战名称
- 总时长
- 阶段列表
- 主目标配置
- 子目标配置
- 成功条件
- 失败条件
- 奖励配置
- 出生/传送点
- 目标朝向点
- 开场 Sequence
- 开始前倒计时
- 挑战 BGM
- Tips 触发配置
- 挑战物件加载配置
- 死亡回点配置
- 退出与失败后的处理规则
